# モノの記憶 (Technical Specification / README)

本ソフトウェアは、画像特徴抽出モデルを用いた物体照合によってアクセス制御を行い、端末ローカル環境でファイルおよびテキストデータを保持・暗号化エクスポートするWebアプリケーション（PWA）です。

---

## 1. システム構成・動作環境

* **種別**: Progressive Web App (PWA) / シングルページアプリケーション
* **実行環境**: モダンブラウザ（Safari, Chrome等。Web Crypto API, IndexedDB, WebAssembly対応必須）
* **ネットワーク通信**:
  * 初回起動時のみ：推論エンジンおよび学習済みモデル重みファイルの取得（CDN経由）
  * 運用時：通信不要（完全ローカル動作。外部サーバーへのデータ送信処理なし）

---

## 2. 動作原理とアルゴリズム

### 2.1 画像特徴抽出 (Feature Extraction)
* **モデル**: `DINO (Vision Transformer Small, Patch Size 16 / ViT-S/16)` 量子化ONNXモデル
* **入力前処理**:
  1. 撮影画像から中央領域を正方形にクロップ（Center Square Crop）。
  2. 800×800ピクセル（品質0.85）にリサイズ。
  3. モデル内部で224×224ピクセルに再サンプリングおよび正規化。
* **特徴量合成（ハイブリッドベクトル）**:
  1. 出力テンソル形状：`[1, 197, 384]`（CLSトークン1個 ＋ パッチトークン196個）。
  2. CLSトークン（大局的形状情報：384次元）を取得。
  3. 全196パッチの要素ごとの平均値（局所的テクスチャ情報：384次元）を算出。
  4. 両者を加算合成し、L2正規化を実行。
     $$\mathbf{v} = \frac{\mathbf{x}_{\text{CLS}} + \frac{1}{196}\sum_{i=1}^{196} \mathbf{x}_{\text{patch}, i}}{\left\| \mathbf{x}_{\text{CLS}} + \frac{1}{196}\sum_{i=1}^{196} \mathbf{x}_{\text{patch}, i} \right\|_2}$$
  5. 最終出力：384次元の単位ベクトル。

### 2.2 回転耐性（Gallery-side Augmentation）
* 登録時、基準画像（0°）からCanvas操作により90°、180°、270°回転した3画像を生成。
* 各画像から特徴ベクトルを抽出し、計4つの384次元ベクトルを1つのキーセットとして保存。
* 照合時は1回の撮影で得たベクトルに対し、登録側の各回転ベクトルとコサイン類似度を算出。

### 2.3 照合判定 (Matching)
* **類似度計算**: 正規化済みベクトル間の内積（コサイン類似度: $-1.0 \le s \le 1.0$）。
* **判定論理**:
  * 対象アイテムが保持する全ベクトル（登録アングル数 × 4回転）との類似度を計算。
  * 最大値（$\max(s)$）がアイテムに設定された閾値（標準: 0.75 / 厳格: 0.82 / 寛容: 0.70）以上の場合に認証成功と判定（OR条件）。

## 3. セキュリティと暗号化仕様

二層の独立した暗号化スタックで構成されます。

### 3.1 端末内保存時（安静時暗号化: Encryption at Rest）
* **鍵管理**:
  * 初回起動時に `crypto.subtle.generateKey` により AES-GCM 256bit 鍵を生成。
  * `extractable: false` に設定され、JavaScriptから秘密鍵の生バイナリを出力不可。
  * IndexedDB内の `meta` ストアに CryptoKey オブジェクトとして格納。
* **暗号化対象**:
  * `FILE LOCK`: 添付ファイルのバイナリおよびファイル名。
  * `MASKED` / `HIDDEN`: 名称、メモ、写真、添付ファイルのバイナリ全体。
* **暗号化形式**:
  * 暗号方式: AES-256-GCM
  * IV: 12バイト（暗号化ごとに `crypto.getRandomValues` で生成、暗号文先頭に付与）
  * 認証タグ: 16バイト（GCM標準）

### 3.2 外部エクスポート時（可搬暗号化ファイル: `.encbak`）
* **鍵導出**:
  * アルゴリズム: PBKDF2
  * ハッシュ関数: SHA-256
  * ストレッチング回数: 150,000回
  * Salt: 16バイト（乱数生成）
* **暗号化形式**:
  * 導出鍵による AES-256-GCM 暗号化。
  * データ構造: `[Salt (16B)] + [IV (12B)] + [Ciphertext + Tag (可変)]`
* **オプション**: メモ文字列を除外し、添付ファイルのみを暗号化出力することが可能。

### 3.3 セッション管理
* 復号されたデータ（画像Blob、平文テキスト、ファイル実体）はブラウザのRAM（JavaScript実行コンテキスト内のMap）にのみ保持。
* 以下のトリガーでRAM内の復号キャッシュおよびセッションID（Set）をクリア：
  1. 「一覧に戻る」ボタンの押下
  2. 下部ナビゲーションによるタブ切り替え
  3. ブラウザの `visibilitychange` イベント検知（タブの非アクティブ化、アプリ最小化、タスクスイッチ）

## 4. 機能仕様

### 4.1 保護レベルの定義

| レベル | 一覧での表示 | IndexedDB上の保存状態 | アンロック条件 |
| :--- | :--- | :--- | :--- |
| **STANDARD** | 写真・名称を表示 | 平文 | 常時アクセス可能 |
| **FILE LOCK** | 写真・名称を表示 | 写真・名称は平文、**ファイルのみ暗号化** | カメラ照合でファイル閲覧・取得可 |
| **MASKED** | 写真・名称を伏字化 | **写真・名称・メモ・ファイルを暗号化** | カメラ照合で全項目がRAM上に展開 |
| **HIDDEN** | **一覧から除外** | **写真・名称・メモ・ファイルを暗号化** | カメラ照合時のみ検知・RAM上に展開 |

### 4.2 マルチキー登録（OR条件認証）
* 1つの記録IDに対して、複数の写真（および各4回転ベクトル）を追加登録可能。
* 登録されたキーのいずれか1つと合致すれば照合成功とみなす。
* 詳細画面では登録済みキーのサムネイルをタップしてプレビューの切り替えが可能。

### 4.3 重複検知
* 撮影直後、登録済みの全ベクトルと照合を実行。
* 類似度が 0.82 以上の既存データが存在する場合、警告を表示し、既存データの閲覧または強制保存の選択を要求。
* 衝突対象が `MASKED` または `HIDDEN` の場合、名称を出力せず「保護された記録」と表示。

## 5. 撮影条件とモデル特性

### 5.1 推奨撮影条件
* **被写体サイズ**: 画面の50%〜70%を被写体が占める画角（背景面積の比率を下げるため）。
* **背景**: 単一色またはテクスチャの少ない面。近傍に文字印刷物や別の独立した物体を置かないこと。
* **無地物体**: ロゴ、印字、境界線など幾何的特徴のある面を撮影面とする。

### 5.2 DINOモデルの認識特性
* 画素（RGB）の絶対値ではなく、境界・エッジ構造およびパッチ間のアテンション（関連度）を重視して特徴量を抽出する。
* **挙動の例**: テレビを被写体とした場合、画面内の放映映像が変動しても、外枠（ベゼル）、アスペクト比、スタンド等の構造的特徴量が支配的となるため、同一物体として判定される。

## 6. 制約事項と留意点

1. **データ永続性**:
   * データはブラウザの IndexedDB に依存。ブラウザ側で「サイトデータ消去」や「履歴削除」を実行した場合、データは消去される。
   * iOS Safari等の仕様により、端末ストレージ容量が極度に逼迫した場合にブラウザデータがOSによって整理される可能性があるため、定期的なエクスポート（`.encbak`）が必要。
2. **暗号化の不可逆性**:
   * エクスポート時に設定したパスワードはハッシュ化等の保存を行わないため、紛失時の復旧手順は存在しない。
3. **ストレージ容量**:
   * 添付ファイルはBase64シリアライズおよびBlob経由でIndexedDBに格納される。数百MB以上のファイルを多数保持するとブラウザのストレージクォータ制限（QuotaExceededError）に抵触する。
